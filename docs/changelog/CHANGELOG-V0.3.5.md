## 本次重点

导出 Word（.docx）**与预览不一致**的问题，从字号、行高、配色到内容完整性逐条修完：**不再丢内容**（公式、脚注、分隔线、元信息），**排版跟随你在设置里选的预览字号/行高**，暗色主题也不再导出成「白纸上的荧光字」。另外补齐两条以前做不到的能力：**公式导出为 Word 原生可编辑公式**、**SVG 导出为矢量图**。

## 新功能

### 公式：导出为 Word 原生可编辑公式

- 行内 `$…$` 与块级 `$$…$$` 现在转换成 **Word 原生公式（OMML）**：在 Word / WPS 里可以点进公式编辑框、能直接改字符，和 Word 自己插入的公式是同一种东西；块级公式整组居中
- 转换完全离线：vendor 了 MIT 许可的 **tex2word-math 1.0.6** 源码（`src-tauri/src/omml/`，同目录附 `LICENSE-MIT` 与出处说明）。不启动外部进程、不联网、不依赖 Office
- 覆盖常见写法：分式、根式（含 `\sqrt[3]{}`）、上下标、求和/积分（含上下限）、希腊字母、`\mathbb`/`\mathcal`/`\vec`/`\hat`/`\bar`、`\text{}`、矩阵、`cases`、`aligned`、`\binom`、`\operatorname` 等
- **绝不丢内容**：引擎不认识的宏若整段都转换不出内容，自动退回原来「等宽 TeX 源码」的显示方式（宁可显示源码，也不出现空白公式）
- 已知限制：不支持公式编号 `\tag` 与交叉引用（预览的 KaTeX 也没有）；`{}^{14}C` 这类前置上标会退化

### 图片：SVG 导出为矢量（并带位图回退）

- 此前 SVG 图片会被跳过；现在 SVG **同时**写入矢量部件（`asvg:svgBlip` 扩展）与 PNG 回退位图
- Word 2016+ / 365 与 WPS 走矢量：**放大不糊**；旧版 Word / LibreOffice 走回退位图——LibreOffice 在没有回退图时会**整张空白**（tdf#126084），所以回退图不能省
- 回退位图用纯 Rust 的 resvg 栅格化（`text` + `system-fonts`：SVG 里的文字、中文都能正确渲染，不会变成空白或方框）
- 尺寸取 SVG 的**固有尺寸**（按 96dpi 换算：240×120 px 的 SVG → 180×90 pt，与 Word 自己插入时一致），不会因为栅格化倍率而变大

### 代码块：语法高亮与预览逐 token 一致

- 此前导出的 Word 里代码块**没有着色**（等宽 + 底色 + 缩小一号，但全是单色）
- 现在导出前由前端**从预览 DOM 直接读取** highlight.js 的分词结果与每个片段的实际颜色/粗体/斜体，随主题一起传给导出器 —— 因此与你在预览里看到的代码着色**逐 token 一致**：换主题、改自定义 CSS（`--code-*` 令牌）都会自动跟随，不需要在导出器里另猜一套配色
- 已知边界：**缩进式代码块**（四个空格）预览本来就不着色，导出同样单色；被插件改写成非代码块的围栏（如 mermaid 图）也不会硬套代码配色；导出瞬间预览若还没跟上（预览渲染有 150ms 防抖），该代码块退回单色，文字与换行不受影响
- **暗色主题**：页面上的 token 是按深底配的亮色（如 `#67e8f9`），白底 Word 里会压到白底可读的亮度（**保留色相**，与正文/底色/边框的「白底等效色」同一套规则）；浅色主题原样搬预览颜色

### 正文列宽度：拖拽边缘调宽

- 正文列左右边缘各藏着一个**看不见的手柄**：鼠标移到那儿才浮现一条主题色短竖线（上下两端淡出、跟着光标走），按住左右拖即可调正文宽度，双击恢复默认 900px
- **源码 / 实时 / 预览共用一个宽度**：拖一次三种模式一起变；窄窗口下仍然自动收窄，不会溢出或出现横向滚动条
- 并排模式不显示手柄（两列各有各的居中列）；默认 900px 与源码模式此前一致，部分主题的预览宽度原先固定 800/700px，现在跟随这个统一值

## Bug 修复

### 导出的 Word 与预览字号/行高/配色不一致

- **字号行高此前根本没传给导出**：不管你在设置里把预览字号调成多少，导出的 Word 一律是固定 11pt、1.5 倍行距。现在导出正文＝你设置的**预览字号**，行距＝设置的**预览行高**，段落间距、列表间距、标题字号也全部按同一比例换算（标题跟随预览比例：一级 2 倍、二级 1.5 倍、三级 1.25 倍，四级及以下与正文同号仅加粗）
- **暗色主题导出后不可读**：主题的正文色/底色是给深色屏幕配的，而 Word 页面恒为白底，于是出现「白纸上的荧光绿字 + 近黑底色」。现在暗色主题导出时改用白底等效配色，主题强调色保留原来的色相、只压到在白纸上看得清的亮度
- 同步补齐 Word 文档默认字体/字号/语言标记，标题、代码块、引用、表格的表头底色与网格线、代码底色等取值都与预览主题变量一致（不再有写死的灰色）

### 导出的 Word 会丢内容

- **数学公式整段消失**：行内 `$公式$` 与块级 `$$公式$$` 都不见了，块级公式还留下一个空段落。现在导出为 **Word 原生可编辑公式**（见上文「新功能」）；万一引擎转换不出内容，退回原样保留 TeX 源码（行内等宽、块级居中），任何时候都不会丢公式
- **脚注：引用消失、定义文字跑进正文**：现在导出为 Word **原生脚注**（正文处是上标序号，文字在页面底部），不再把定义文字当正文段落。只有「写了定义且正文真的引用了」的脚注才转换；只写定义没引用的，仍按普通段落输出（不会凭空消失）；引用了却没写定义的，按原文 `[^x]` 显示
- **Front matter（开头 `---` 之间的元信息）漏成正文第一段**：现在整块丢弃，与预览/HTML/PDF 一致
- **分隔线 `---` 整条消失**：现在导出为一条横线
- **工具条的上标/下标丢失、手写 `^x^` 会把整段拆成好几段**：工具条插入的 `<sup>`/`<sub>` 现在能正确还原为上下标；`^x^`/`~x~` 这类预览**不支持的拓展语法**则保持字面（否则会出现「预览是 `^x^`、Word 里却成了上标」的不一致）；`<u>` 下划线、`<mark>` 高亮、`<br>` 换行等行内 HTML 也会正确还原

### 列表编号与任务列表

- **第二个有序列表接着上一个继续编号**（从 5、6 接着数，而不是重新从 1 开始），`3.` 开头的列表起始序号也被忽略 —— 均已修正：每个列表（**包括嵌套列表**）都独占 `w:num` **与 `w:abstractNum`**，编号必然实例内独立，起始序号生效
- **嵌套有序列表在 Word 里变成 `1.1.` 多级编号**（预览里每一级都是 `1.`，缩进靠层级）：现在嵌套层也各自从 `1.` 开始，缩进按层级递增，与预览一致
- **任务列表出现「项目符号 + 勾选框」双重标记**：现在只保留 ☑/☐ 勾选框，缩进与普通列表对齐

### 图片

- **WebP 图片在 Word/WPS 里显示为空框**（WPS/Word 不支持 WebP）：导出时自动转成 PNG 再嵌入；万一转码失败会保留原图并在日志里说明
- **部分图片被静默丢弃**：此前只按扩展名判断图片类型，扩展名是 `.jfif`、没有扩展名、或扩展名写错的图片会被丢掉或按错误类型嵌入。现在以文件内容为准（SVG 这类没有魔数的文本图像也能按内容识别），真正不支持的格式会跳过并在日志中提示，不再一声不响

### 其他一致性

- **标点不再被悄悄替换**：预览关闭了「智能标点」，导出却会替换 —— 直引号 `"` 变中文引号、`a--b` 变 `a–b`、`...` 变 `…`。现在与预览一致，保持原文
- **裸网址自动变成链接**（与预览的 linkify 一致）；`[[双链]]` 不再生成打不开的无效链接，按原文显示
- **代码块的行距与段落结构**：一个代码块现在是**一个段落**（行内用软换行），不再是「每行一个段落」——末尾不再多出空段落，复制/选中也不会被切成多段（换行本身丢失的问题见下文「第一轮实机验收后修的问题」）
- **表格补上列宽网格**：此前 Word 需要自己猜列宽，多列表格容易宽窄不齐

### 第一轮实机验收后修的问题（同 0.3.5）

- **同段内的换行全部失效、文字挤成一行**：软换行、行尾两空格、行尾反斜杠三种写法在 Word 里都不换行，代码块的多行也被合并成一行。原因是换行符 `<w:br/>` 被写到了段落里、而不是 run 里 —— 它是 **run 级元素**，Word/WPS 对不合法的段落内容会整段忽略。三处换行（软/硬换行、行内 `<br>`、代码块行间）现在都写在 run 内
- **嵌套有序列表把父级序号带跑**（「第一章、第一节、第二节、第二章」里第二章变成了 3）：编号计数器挂在 `w:abstractNum` 上，此前各列表虽然各有 `w:num` 实例，却**共享同一个 `w:abstractNum`**，只靠 `startOverride` 重置 —— WPS 因此让二级列表（第一节、第二节）把父级计数器推到了 3。现在**每个列表（含嵌套）独占一个 `w:abstractNum`**，`w:start` 同时写在层级与覆盖里
- **引用块导出后「没有层级、还被打断成好几段」**：此前每个段落各画一条左边框与底色，段间距处露出缺口（WPS 不合并相邻段落的边框），嵌套引用只体现为缩进。现在整块引用渲染为一个**单元格表格**：左边框（3pt 主题色）与底色连续不断，嵌套引用是父单元格里的内层表格，层级由单元格外边距逐级递进（对应预览的 `padding: 0.5em 1em`），不再有任何段落级边框
- **脚注里的文字比脚注正文大一圈**：脚注里的列表项沿用 `ListParagraph`（基于正文样式）、多段脚注的第二段是 `Normal`、行内代码按**正文字号**的 0.9 倍计算 —— 脚注内部字号参差不齐。现在脚注上下文统一以「脚注字号」（正文的 0.83 倍，Word 惯例）为基准：脚注内的每一段、每一个 run、行内代码（脚注字号的 0.9 倍）都显式写小字号，且不会影响正文
- **预览里任务项的行内代码/加粗被挤成「行内硬换行」、内容重复出现两遍**（预览侧的渲染缺陷，不是导出问题）：`markdown-it-task-lists` 的 `labelAfter: true` 会把**原始 Markdown 文本**（含反引号与 `**`）再插一份 `<label>`，于是内容渲染两遍，且两个行内块在 flex 布局里各成一个 flex 项、宽度不足时被逐个挤压。现在改用 `labelAfter: false`（`<label>` 包住勾选框与内容），容器里只有一个子项，宽度不足时按普通文本在容器边缘折行
- **代码块没有语法高亮**：现在从预览读取 highlight.js 的分词与实际颜色传给导出器，逐 token 与预览一致（详见上文「新功能 → 代码块」）；代码块被合并成一行的换行问题同属上面第一条

### 导出 Word：无序列表的项目符号变成方框、且层级越深越大

- 第一轮导出：项目符号显示成**方框或错误字符**；用鼠标选中那个符号，字体栏显示的是 `Symbol`
- 原因：项目符号本身是 Unicode 字符（`•` `○` `■`），却同时被指定用 **Symbol 字体**渲染。而 Symbol 字体里**根本没有这几个字符**——它只收录 `0x00–0xFE` 与 `0xF020–0xF0FE` 两段码位，Word 自己导出时写的是私有区码位（`U+F0B7`）。码位和字体对不上，Word 就找不到字形
- 去掉强制字体后**又暴露第二个问题**：三级符号 `•` `○` `■` 是**层级越深越大**。实测字形墨迹（WPF 逐字形度量，em = 100）：MiSans 里 `•` 只有 29.0，`○` 却有 72.4、`■` 70.0 —— 二三级看上去是正文字号的两倍半
- 最终方案：一级 `•` 跟随正文字体；二/三级改用与 `•` **同尺寸**的小码位 `◦ U+25E6` / `▪ U+25AA`（雅黑实测 27.5 / 24.5，与 `•` 的 27.5 相当），并只在「正文字体确实没有这个字形」时才显式指定字体。`fontTable.xml` 为它挂了替代名链（Segoe UI Symbol → PingFang SC → Apple Symbols → Arial Unicode MS → DejaVu Sans），macOS 与没装雅黑的 Windows 上也不会变方框
- 四级及以后循环 `•` `◦` `▪`（对应预览 `ul` / `ul ul` / `ul ul ul` 的 disc / circle / square）

## 其他

- 版本号 0.3.5
- 安装包/便携版的 `docs/` 目录现在随版分发**完整文档**：主题规范 `THEME-DESIGN-SPEC.md` 此前漏发了（想写自定义主题、查令牌含义就看它，位置是程序目录下的 `docs/`，帮助里也加了指引）；同时**不再附带开发日志 `changelog.md`**（261 KB 的完整技术记录，只对开发者有意义，仓库里仍然保留）

- **0.3.5 是第一个可以在应用内一键更新的版本**：0.3.4 及更早版本仍需手动下载安装本次更新；从本次起，以后的新版本就能在「设置 → 版本与更新」里直接更新了
- 新增两个第三方组件（许可证与出处都随源码留在仓库里）：**resvg**（`Apache-2.0 OR MIT`，纯 Rust SVG 渲染，用于生成回退位图）与 **tex2word-math 1.0.6**（`MIT`，公式转 OMML，源码 vendor 在 `src-tauri/src/omml/` 并附 `LICENSE-MIT`）。两者都不启动外部进程、不联网
