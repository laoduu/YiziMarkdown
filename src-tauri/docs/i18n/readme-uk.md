# YiziMarkdown


![image](https://github.com/laoduu/YiziMarkdown/raw/main/assets/readme/index.png)

[简体中文](../../readme.md) | [繁體中文](./readme-zh-TW.md) | [English](./readme-en.md) | [日本語](./readme-ja.md) | [한국어](./readme-ko.md) | [Deutsch](./readme-de.md) | [Français](./readme-fr.md) | [Español](./readme-es.md) | [Português](./readme-pt.md) | [Italiano](./readme-it.md) | [Polski](./readme-pl.md) | [Nederlands](./readme-nl.md) | [Türkçe](./readme-tr.md) | [Svenska](./readme-sv.md) | [Українська](./readme-uk.md) | [Русский](./readme-ru.md)

**Офіційний сайт:** https://md.yizigpt.com

YiziMarkdown — кросплатформний редактор Markdown, зосереджений на писанні. Один і той самий файл `.md` має сім способів представлення: `редагування вихідного тексту`, `звіряння пліч-о-пліч`, `живий режим`, `перегляд готового результату`, `показ слайдів`, `читання як книжки`, а також `режим дзен`, де лишається тільки текст.

- **Windows**: можна встановити (інсталятор NSIS з оновленням у застосунку одним натисканням) або завантажити портативний архів і запустити одразу після розпакування
- **macOS**: універсальний двійковий пакет, нативно працює на Intel і Apple Silicon
- **Linux**: пакет `deb` для Debian і `AppImage` без встановлення (Ubuntu 22.04+ / Debian 12+, наразі лише amd64)

Навіщо робити ще один редактор Markdown? Наявні варіанти або виглядають непривабливо, або перевантажені функціями, і важко знайти інструмент, що поєднує простоту, красу й зручність роботи. Так з'явився YiziMarkdown, відданий трьом речам: **гарний інтерфейс**, **потужні функції**, **різноманітні сценарії**.

Так і з'явився нинішній `YiziMarkdown`: `підтримка 3 систем`, `7 режимів роботи`, `16 мов інтерфейсу`, `15 світлих і темних тем`, `5 AI Skill`, `7 форматів експорту`, а також вбудований AI-помічник, хмарне сховище та інші новаторські функції, плюс відкрита документація щодо тем, навичок і презентацій — з усього цього можна зібрати власний, ні на що не схожий досвід роботи.

Це вже не простий редактор markdown, а справді багатофункціональний застосунок, що охоплює найрізноманітніші сценарії роботи з документами — творчість, роботу, повсякденне життя.

## Сім режимів: один документ — сім способів представлення

Цінність Markdown не лише в тому, щоб «писати», а й у тому, «кому і як це показувати». YiziMarkdown пропонує одному документові сім способів представлення: перші чотири — це режими редагування, що перемикаються між вихідним текстом і готовим результатом; останні три — окремі сценарії, які перетворюють документ на слайди, книжкові сторінки або взагалі лишають тільки текст.

| Режим | Однією фразою | Вхід | Кому підходить |
|------|-----------|------|------|
| Вихідний текст | Пряме редагування вихідного Markdown | `F3` / кнопки вигляду | Точне доопрацювання структури, масова заміна, front matter |
| Пліч-о-пліч | Ліворуч пишете, праворуч одразу звіряєте | `F3` / кнопки вигляду | Вичитування верстки, писання за шаблоном |
| Живий | WYSIWYG, розмітка ховається автоматично | `F3` / кнопки вигляду | Довгі тексти, зосереджене писання |
| Перегляд | Показується лише підсумкова верстка | `F3` / кнопки вигляду | Перевірка результату, читання цілком |
| Показ | Документ одразу показується слайдами | `Ctrl+Alt+P` / панель інструментів | Поділитися, звіт, лекція |
| Читання | Документ верстається в книжку, яку можна гортати | `Ctrl+Alt+R` / панель інструментів | Довге читання, EPUB, занурення в текст |
| Дзен | Інтерфейс зникає, лишається тільки текст | `F9` / панель інструментів | Глибоке писання |

`F3` перемикає по колу між вихідним текстом / пліч-о-пліч / живим режимом / переглядом; у показу, читання й дзену свої входи, вони не конфліктують.

## Markdown: чотири в одному

![Порівняння чотирьох режимів](https://github.com/laoduu/YiziMarkdown/raw/main/assets/readme/4modes.webp)

Вихідний текст, пліч-о-пліч, живий режим і перегляд використовують одне ядро редактора й один набір можливостей Markdown; різниця лише в «щільності інформації»: від повністю відкритої розмітки до повністю зверстаного результату. Перемикатися можна будь-коли, і вигляд за можливості зберігає поточну позицію.

### Режим вихідного тексту: видно все, що потрібно

- Ядро CodeMirror 6: підсвічування синтаксису, зіставлення дужок, автодоповнення
- Номери рядків і перенесення рядків вмикаються незалежно; підходить для построкового доопрацювання й масових змін
- YAML frontmatter показується як є — під час редагування метаданих не треба вгадувати формат
- Таблиці, блоки коду й формули показуються у вигляді вихідного тексту — найкерованіший варіант для складних структур

### Режим «пліч-о-пліч»: пишете й звіряєте

- Ліворуч вихідний текст, праворуч перегляд, оновлення одразу під час введення
- Синхронізацію прокручування задає структура заголовків; під час перемикання вигляду поточна позиція визначається автоматично
- Підходить для вичитування верстки й перебудови структури за готовим документом

### Живий режим: що бачите, те й отримуєте

- Під час введення розмітка Markdown ховається й повертається, коли курсор залишає це місце, тож ви зосереджуєтеся на змісті
- 4 власні анімації появи розмітки (фокус / спалах / сяйво / брижі), їх можна переглянути й перемкнути в налаштуваннях
- YAML front matter відображається як редагована панель властивостей у стилі Obsidian: авто / текст / число / прапорець / дата / дата й час / список — 7 типів, тип запам'ятовується глобально за назвою властивості

### Режим перегляду: лише результат

- Markdown відрисовується одразу під час писання, прапорці списку завдань можна натискати
- Зображення за локальними шляхами, з мережі та SVG відрисовуються автоматично (jpg / png / gif / webp / svg / bmp)
- frontmatter ховається автоматично — ви бачите підсумкову верстку

### Що спільного в усіх чотирьох виглядах

- **Пошук і заміна**: навігація за збігами, заміна всіх
- **Форматування з панелі**: жирний, курсив, закреслення, вбудований код — виділення одразу обгортається
- **Поліпшення блоків коду**: підсвічування highlight.js, ярлики мов, кнопка копіювання, перемикання перенесення рядків
- **Вибір таблиці**: вставлення за сіткою 8×8 одним кліком, кількість рядків і стовпців видно одразу, додавання й вилучення рядків і стовпців, а також меню за правим кліком — усе під рукою
- **Формули й діаграми**: KaTeX: вбудовані `$...$` / блокові `$$...$$`, Mermaid — блок-схеми, діаграми послідовностей, діаграми Ганта, діаграми класів, кругові тощо, кольори йдуть за темою
- **Згортання панелі форматування**: автоматично згортається, коли вікно звужується, можна розгорнути вручну
- **Номери рядків і перенесення рядків**: вмикаються в налаштуваннях
- **Навігація за структурою**: рівні заголовків беруться зі структури документа й пов'язані з позицією прокручування

## Режим показу: нотатки одним кліком перетворюються на слайди

![Режим показу](https://github.com/laoduu/YiziMarkdown/raw/main/assets/readme/slide.webp)

Готові нотатки більше не потрібно експортувати в PPT: з вбудованою навичкою AI-помічника вони одним кліком стискаються в коротку версію для показу, ви перемикаєтеся в режим показу — і документ одразу стає повноекранними слайдами. Розбиття на сторінки, колонки й макети виводяться зі структури Markdown автоматично; коли потрібен точний контроль, використовуйте директиви в HTML-коментарях.

### Зміст стає слайдами

- Жодного додаткового формату: `---` (горизонтальна лінія) розбиває на слайди
- `***` окремим рядком усередині сторінки ділить її на колонки, максимум 4
- Рушій аналізує структуру сторінки й сам обирає макет: для заголовків, списків, таблиць, коду, зображень і діаграм є свої

### 14 макетів

Обкладинка, сторінка розділу, фінальна сторінка, зміст, вміст, список, таблиця даних, дорожня карта, текст із зображенням, зображення, цитата, код, діаграма (Mermaid), формула.

- Крім «текст із зображенням», який потребує явного `<!-- layout: figure -->`, решта макетів виводиться зі змісту
- Сторінки вмісту вирівняні за лівим краєм, заголовок із підкресленням кольору теми
- На сторінці цитати діагональні великі лапки: відкривні вгорі ліворуч, закривні внизу праворуч, вміст по центру вертикально
- Обкладинка автоматично читає `author` / `date` із front matter

### Керування версткою під час показу

- Налаштування HUD: шрифт (за темою / без зарубок / із зарубками / моноширинний), насиченість, розмір, ширина й висота області вмісту (50%–95%)
- Зміни застосовуються одразу й зберігаються — наступний показ використає їх
- Задовгий вбудований код переноситься, а не обрізається краєм сторінки
- Явні директиви: `<!-- layout: xxx -->` задає макет, `<!-- align: left|center|right -->` вирівнює всю сторінку

### Показ і навігація

- Ліворуч унизу назва розділу й номер слайда, уздовж низу — смуга поступу кольору теми
- `T` відкриває висувний зміст, `G` або поле внизу переходить до слайда
- Колесо миші гортає: якщо вміст прокручується, спершу прокручується він, на межі — перехід
- `F` — повний екран / відновлення, працює з будь-якого стану вікна, зокрема звичайного й розгорнутого
- Після виходу стан вікна відновлюється; кнопка виходу праворуч угорі ховається через 1,5 с бездіяльності
- Успадкування теми: кольори заголовків ідуть за темою, під час показу можна змінювати тему й світлий/темний режим

## Режим читання: документ верстається в книжку, яку можна гортати

![Режим читання](https://github.com/laoduu/YiziMarkdown/raw/main/assets/readme/reading.webp)

Режим читання — це не «перегляд на весь екран», а справжня верстка тексту в фіксовані сторінки: з обкладинкою, титульною сторінкою, змістом, номерами сторінок, а також папером і анімацією гортання.

- Вхід: кнопка книжки на панелі інструментів або `Ctrl+Alt+R`; `Esc` виходить і відновлює попередній вигляд
- Розкладка: тонка рамка з рівними полями з чотирьох боків обрамляє сторінки, дві сторінки з'єднані, між ними лише одна розділова лінія; назва книжки вгорі ліворуч, назва розділу / номер сторінки внизу ліворуч, HUD унизу праворуч — так само, як у режимі показу
- Обкладинка, титульна сторінка й сторінка змісту створюються автоматично: назва береться з front matter `title` або першого H1, зміст будується за заголовками з номерами сторінок і за потреби розбивається на сторінки
- Справжня пагінація: розворот із двох сторінок (у вузькому вікні — одна сторінка), з номерами сторінок і поступом читання

### Анімація гортання

4 варіанти, перемикаються в налаштуваннях, за замовчуванням горизонтальне ковзання:

- **Горизонтальне ковзання** (за замовчуванням): сторінка цілком зсувається — чітко й швидко
- **3D-гортання**: аркуш загинається від нижнього правого кута, складаючись навколо згину, під час гортання папір підіймається, з освітленням і падаючою тінню (в односторінковому режимі — навколо корінця)
- **Плавна поява** / **Масштабування**: спокійніші переходи

Швидкі повторні натискання не пропускають сторінки; переходи за змістом, номерами сторінок і виносками йдуть без анімації.

### Правила розбиття на сторінки

Абзаци розбиваються за рядками, заголовок не лишається сам наприкінці сторінки, заголовок таблиці повторюється на наступній сторінці, блоки коду продовжуються порядково, списки продовжуються за пунктами, зображення цілком масштабується пропорційно; абзаци основного тексту отримують відступ першого рядка на два знаки, на продовженні сторінки відступ не повторюється.

### Навігація й деталі

- Висувний зміст: `T`, список за рівнями заголовків із номерами сторінок, клік веде просто туди
- `G` або поле номера сторінки переходить до вказаної сторінки
- Виноски туди й назад: клік за посиланням веде до сторінки визначення з підсвічуванням, є кнопка «повернутися до посилання»; внутрішні якорі також переходять за сторінками
- HUD читання: унизу праворуч можна перемкнути світлий/темний режим, вибрати тему і шрифт (тема / із зарубками / без зарубок / моноширинний), розмір і міжрядковий інтервал — усе діє лише для поточного читання
- Запам'ятовування позиції: номер сторінки / розділ запам'ятовується за документом, під час повторного входу відновлюється
- Керування: стрілки, PageUp / PageDown, пробіл, колесо, а також клік за лівим або правим краєм сторінки

### EPUB

Відкриття `.epub` одразу вмикає режим читання: використовується тема читання застосунку (CSS видавця ігнорується), читаються вбудована обкладинка, зміст, зображення, формули, Mermaid SVG, виноски й міжрозділові посилання. DRM-шифрування й фіксована верстка (комікси / фотоальбоми) поки не підтримуються.

## Режим дзен: лишається тільки текст

![Режим дзен](https://github.com/laoduu/YiziMarkdown/raw/main/assets/readme/zen.webp)

Вхід за `F9` або кнопкою режиму дзен на панелі інструментів. Панель інструментів, рядок вкладок, бічна панель, AI-панель і рядок стану шарами згортаються до країв екрана й розчиняються, лишається тільки текст; увесь процес **не змінює розкладку**, текст не зсувається ні на піксель.

- **Світ на місці**: притисніть вказівник до будь-якого краю екрана (верх / ліво / право / низ), і відповідна область плавно проступає на колишньому місці; приблизно через 1,2 с після відходу вказівника вона знову згортається
- **Постійний перемикач**: кнопка режиму дзен не зникає й завжди лишається на місці (навколо неї ледь помітні дихальні брижі) — це і якір стану «ви в дзені», і вихід; `F9` / `Esc` також виводять
- **Лише для писання**: доступний тільки в режимах «Вихідний текст» / «Живий»; під час перемикання на «пліч-о-пліч», перегляд або входу в читання / показ він виходить автоматично
- **Чистіший папір**: приховані номери рядків і вертикальні лінії бічної панелі, дуже легка віньєтка, вказівник ховається після 2 с нерухомості; вертикальну смугу прокручування замінено мінімальною тонкою смужкою, що з'являється під час прокручування або біля правого краю

## Файли й писання

### Файли й вкладки

- **Відкриття**: `.md` / `.markdown` / `.txt` / `.epub`, EPUB одразу відкривається в режимі читання
- **Один екземпляр**: кілька відкриваних файлів автоматично зливаються в наявне вікно, повторно відкритий файл перемикає на відповідну вкладку
- **Рядок вкладок**: перемикання, закриття, створення, перетягування для впорядкування
- **Головна сторінка**: список нещодавно відкритих файлів із розміром і часом зміни
- **Стан збереження**: дихальна точка, поки файл не збережено, після збереження — анімація підтвердження ✅
- **Підтвердження закриття**: зберегти / не зберігати / скасувати

### Створення й шаблони

- Нова порожня вкладка показує «Безіменний новий файл»
- «Створити з шаблону» на панелі інструментів створює документ за структурою Markdown вибраного шаблону; у розділі Налаштування → Загальні можна задати шаблон за замовчуванням, і тоді `Ctrl+N` застосовуватиме його
- Шаблони зберігаються в каталозі користувача, достатньо покласти `.md`, також можна створювати / редагувати їх у розділі Налаштування → Шаблони

### Вставлення як Markdown

Форматований текст, копійований із вебсторінок, Word / DOCX, Google Docs, Notion тощо, під час вставлення в пам'яті перетворюється на чистий Markdown (заголовки / списки / таблиці / код / цитати / посилання); готовий вихідний текст Markdown і звичайний текст вставляються як є.

### Збереження й експорт

- **Збереження / автозбереження**: ручне збереження + настроюваний інтервал (5–180 с, за замовчуванням 60 с)
- **Зберегти як**: під час збереження нового файла автоматично відкривається діалог «Зберегти як»
- **Експорт**: HTML / Markdown / звичайний текст / Word (DOCX) / PDF / PPTX / EPUB
  - DOCX використовує нативну семантику Word (списки, таблиці, блоки коду, цитати, списки завдань), стилі таблиць відповідають перегляду, зображення підтримують локальні шляхи, мережеві зображення й HTML `<img>` (ширину можна задати через `width`)
  - PDF збігається з переглядом за точністю й розбивається на сторінки автоматично
  - HTML доповнюється плаваючою карткою змісту ліворуч, клік за пунктом веде до розділу (у PDF бічної панелі немає)
  - PPTX успадковує тему, світлий/темний режим і макети режиму показу, видає редагований текст, таблиці, зображення, фігури й нативні формули
  - EPUB надається вбудованим плагіном; перед експортом можна вибрати розбиття за розділами / обкладинку / видимий зміст / тему читання / відомості про документ
- **Зв'язування файлів `.md`**: у налаштуваннях одним натисканням призначається редактор Markdown за замовчуванням у системі (реєстр Windows / macOS LaunchServices)

### Хмарне сховище (WebDAV)

- **Переглядач файлів**: вкладка «Хмара» на бічній панелі показує дерево каталогів сервера, дає змогу відкривати документи, створювати файли / теки, перейменовувати, переміщувати, вилучати; навігаційний ланцюжок глибокого каталогу згортається в «…» з випадним переходом, теки завантажуються в міру переходу
- **Збереження в хмару**: локальний документ завантажується одним кліком, зображення, на які він посилається за відносними шляхами, завантажуються разом із ним зі збереженням структури каталогів; `Ctrl+S` для хмарного документа одразу записує зміни назад
- **Захист від конфліктів**: перед збереженням порівнюється ETag, якщо файл змінено іншим пристроєм, з'являється діалог із вибором «перезаписати версію на сервері» або «відмовитися від локальних змін і перезавантажити» — мовчазного перезапису не буває
- **Безпека облікових даних**: ім'я користувача й пароль зберігаються в системному сховищі облікових даних (Диспетчер облікових даних Windows / ключниця macOS) і не пишуться у файли конфігурації
- **Сумісність**: стандартні сервіси WebDAV, як-от Nutstore, Nextcloud, Synology (рекомендується пароль застосунку)

## Розробка

### Вимоги

- Node.js 18+
- Rust (stable)
- Tauri CLI (`npm install -g @tauri-apps/cli`)

### Запуск сервера розробки

```bash
cd code
npm install
npm run tauri:dev
```

### Значок у доці в режимі розробки під Linux (необов'язково)

Такі робочі середовища, як elementary / GNOME, шукають однойменний `Icon` у `.desktop` за `WM_CLASS` вікна; у режимі розробки інсталятора немає, отже, немає й `.desktop`, і док показує лише загальний значок (сам `_NET_WM_ICON` вікна вже додано з боку Rust, на інсталяційні пакети це не впливає). Виконайте один раз:

```bash
npm run dev:icon           # записує ~/.local/share/applications/yizimarkdown-dev.desktop
npm run dev:icon:remove    # скасовує
```

Потім перезапустіть вікно розробки — док покаже значок застосунку.

### Збирання релізу

**Windows**

```bash
npm run tauri:build
```

Артефакти:
- Портативний exe: `src-tauri/target/release/yizimarkdown.exe`
- Інсталятор NSIS: `src-tauri/target/release/bundle/nsis/`

Інсталятор: під час першого встановлення спершу вибирається мова встановлення (16 варіантів — усі мови інтерфейсу застосунку + бразильська португальська); тексти майстра й мова першого запуску після встановлення йдуть за цим вибором; оновлення / автооновлення не скидають вибрану мову. Значки й графіка бічної панелі / заголовка лежать у `src-tauri/installer/`; після зміни фірмових кольорів перезапустіть `powershell -ExecutionPolicy Bypass -File scripts/make-installer-art.ps1` для генерації.

Після збирання вручну копіюйте exe і файли ресурсів у каталог `public/YiziMarkdown-vX.X.X/` для поширення.

**macOS (універсальний двійковий файл, одночасно Intel і Apple Silicon)**

```bash
rustup target add aarch64-apple-darwin
npm run tauri:build -- --target universal-apple-darwin
```

Артефакти:
- Пакет застосунку: `src-tauri/target/universal-apple-darwin/release/bundle/macos/YiziMarkdown.app`
- Інсталятор: `src-tauri/target/universal-apple-darwin/release/bundle/dmg/YiziMarkdown_<ver>_universal.dmg`

**Linux (deb + AppImage)**

```bash
sudo apt install libwebkit2gtk-4.1-dev build-essential libssl-dev libayatana-appindicator3-dev librsvg2-dev patchelf
npm run tauri:build -- --bundles deb,appimage
```

Артефакти (**наразі лише amd64 / x86_64**; `arm64` deb і `aarch64` AppImage для ARM поки не публікуються):
- Пакет для Debian: `src-tauri/target/release/bundle/deb/YiziMarkdown_<ver>_amd64.deb` (близько 16 МБ, встановлюється в `/usr/bin`, реєструє пункт меню, значок і зв'язок файлів `.md` / `.epub`)
- Універсальна версія без встановлення: `src-tauri/target/release/bundle/appimage/YiziMarkdown_<ver>_amd64.AppImage` (близько 100 МБ, включає GTK / WebKit і медіакомпоненти GStreamer, запускається подвійним кліком)

Увага: **збирати треба на Ubuntu 22.04**. Двійкові файли, зібрані на 24.04, потребують glibc 2.39 і одразу не запускаються на Ubuntu 22.04 (2.35) / Debian 12 (2.36); залежність `deb` від `libwebkit2gtk-4.1-0` також задає нижню межу Ubuntu 22.04 / Debian 12 (у Debian 11 є лише webkit 4.0). `rpm` поки не надається: у Fedora / openSUSE інші назви залежностей, їх треба підтримувати окремо.

## Версії й оновлення

Встановлена версія для Windows оновлюється в застосунку одним натисканням; macOS, Linux і портативна версія під час запуску перевіряють `latest.json`, і коли з'являється нова версія, унизу праворуч показується сповіщення з посиланням на сторінку завантаження відповідної версії (заміна вручну, без автоматичного встановлення; для Linux цим шляхом ідуть і `deb`, і `AppImage`).
